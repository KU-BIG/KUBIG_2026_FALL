# 곤지암리조트 식음업장 수요예측 — LG Aimers 7기 (DACON 236559)

> **"이 프로젝트에서 점수를 만든 것은 더 큰 모델이 아니라, 평가식이 무엇을 벌하고 무엇을 봐주는지에 대한 이해였다."**

리조트 내 9개 식음업장 · 193개 메뉴의 일별 판매량을, **28일치 관측 창(window)만 보고 다음 7일**을 예측하는 시계열 수요예측 프로젝트입니다. 대회 규정상 허용된 정보(28일 창 + 공휴일·요일 등 달력 지식)만으로 경쟁 순위 1위(0.437)와 0.0006 차이인 **Private SMAPE 0.4376**을 달성했고(Tier A), 이후 대회 규정 밖의 외부 데이터(기상·방문객수)를 결합한 확장 트랙에서 **0.4327**까지 개선했습니다(Tier B).

**이 저장소가 보여주려는 것은 최종 점수가 아니라 과정입니다.** 채택된 개입은 4개, 기각된 축은 15개가 넘습니다. 무엇을 왜 시도했고 왜 버렸는지가 `experiments/log.md`에 사전등록·판정 기준과 함께 전부 남아 있습니다. 아래 방법론은 그 기록을 바탕으로 정리한 것입니다.

| | Private (전체 테스트 1년) |
|---|---|
| 첫 제출 (기본 LightGBM) | 0.4607 |
| **Tier A 최종 (v24, 대회 규정 준수)** | **0.4376** (1위와 0.0006차) |
| **Tier B 최종 (x3, 외부데이터 결합)** | **0.4327** (Tier A 대비 -0.0049) |

## 📌 문제 정의

### 대회 구조가 만드는 제약

| 제약 | 내용 | 이것이 문제를 어렵게 만드는 이유 |
|---|---|---|
| 관측 창 28일 | 예측 시점마다 직전 28일치 판매량만 주어짐 | 연 단위 계절성(스키 시즌·단풍철)을 창 안에서 직접 관측할 수 없음 — 달력 지식으로 추론해야 함 |
| 학습 기간 1.5년 | 2023-01 ~ 2024-06 | 연도별 반복 패턴(작년 동기 대비)을 학습할 표본이 1회뿐 → 사실상 불가능 |
| 테스트 10구간·1년 | 2024-06 ~ 2025-05를 덮는 10개 독립 구간 | 학습연도와 시차가 최대 11개월까지 벌어짐 → "학습기간에 외운 절대 수준"이 시차가 멀수록 무너짐(뒤 "핵심 발견" 참조) |

### 두 개의 트랙 — Tier A(대회 규정)와 Tier B(확장)

> 🚨 **성적의 경계선을 흐리지 않는 것이 이 프로젝트에서 가장 중요한 원칙 중 하나입니다.**

- **Tier A**: 대회가 허용한 정보(28일 창 + 공휴일·요일 등 달력 도메인 지식)만 사용. 리더보드와 비교 가능한 유일한 트랙.
- **Tier B**: 기상청·네이버 데이터랩·방문객수 등 외부 API 데이터를 결합한 확장 트랙. **대회 규정 밖**이므로 버전 번호 체계를 아예 분리하고(`v24`가 아닌 `x1`, `x3` …), 성적표를 Tier A와 절대 같은 표에 섞지 않습니다. 섞는 순간 "우리 최종 성적이 얼마였는가"를 아무도 답할 수 없게 되기 때문입니다.

## 🤖 왜 이 방법론인가 — "더 큰 모델"이 아니라 "손실함수를 이해하는 것"

처음에는 다른 캐글류 대회처럼 하이퍼파라미터 탐색과 알고리즘 앙상블(LightGBM+XGBoost+CatBoost)이 점수를 만들 것이라 가정했습니다. 실제로는 정반대였습니다.

```
v1   0.4607  ┃ 기준선: 글로벌 LightGBM · 피처 57 · 시드 5 평균
             ┃
v8   0.4570  ┃ ← 하이퍼파라미터 79개 탐색 + 앙상블 7건        +0.0037 (17%)
             ┃
v9   0.4439  ┃ ← ① 3구간 후보정                             +0.0131 (61%)
             ┃
v12  0.4412  ┃ ← ② 정수 격자 스냅                            +0.0026 (12%)
             ┃
v17  0.4391  ┃ ← ③ 클램프 임계 2.0 → 1.8                     +0.0021 ( 9%)
             ┃
v24  0.4376  ┃ ← ④ 중복 피처 3개 제거                         +0.0015 ( 6%)
```

모델 튜닝(79개 설정 탐색)이 만든 개선은 전체의 17%뿐이었고, **평가식(SMAPE)의 수학적 성질을 이용한 후처리 세 가지가 나머지 82%를 만들었습니다.** 이 발견 이후 프로젝트의 설계 철학이 바뀌었습니다: "모델을 더 정교하게 만들자"가 아니라 "**이 손실함수가 어떤 예측 패턴을 벌하는지 먼저 증명하자**"로.

그 증명의 핵심 하나만 소개하면 — SMAPE 항 `2|A-P|/(A+P)`를 비율 `r = A/P`로 바꿔 쓰면 `φ(r) = r/(1+r)²`이고 **φ(r) = φ(1/r)**입니다. 즉 손실이 **로그 비율에 대해 대칭**입니다. 실측값은 항상 정수이므로, 이 대칭성 때문에 두 정수 사이의 예측은 항상 손해입니다(예: 실측이 1 아니면 2일 때 기대손실은 P=1.5가 P=1이나 P=2보다 나쁨). 그래서 예측을 정수 격자에 사영하면 이득이 나는데, 이때 반올림 경계는 산술 중점(1.5)이 아니라 **기하 중점 `√(k(k+1))`** (1↔2 경계는 1.414)이어야 옳습니다. **맞출 파라미터가 0개인 개선**이라 어떤 모델의 예측에도 그대로 유효합니다 — 실제로 팀원의 전혀 다른 모델(Ridge)에 얹었을 때도 재학습 없이 +0.0072를 얻었습니다.

## 🧩 핵심 컴포넌트

### 1. 데이터 계층 — `config.py` · `dataio.py` · `preprocess.py`

**`config.py`**는 모든 모듈이 참조하는 단일 설정 소스입니다. 경로, 대회 상수(WINDOW=28, HORIZON=7, N_TEST=10), 도메인 지식(업장별 성수기 군집 5종, 화담숲 개장일·스키시즌·단풍시즌 기준일, 한국 공휴일 2023~2025)을 하드코딩 없이 여기 한 곳에 모읍니다. 데이터 무결성 기준값(`EXPECTED`: 학습행 102,676개·193품목·9업장 등)을 `check_data.py`가 매번 대조합니다.

**`dataio.py`**는 원본 CSV(long: 날짜·품목키·판매량)를 (193품목 × 날짜) 행렬로 변환합니다. 품목 순서는 제출 템플릿의 열 순서로 고정되어, 파이프라인 전체에서 이 순서가 절대 바뀌지 않습니다.

**`preprocess.py`**는 이상치 캡핑을 실험했으나(품목별 상한값을 학습구간의 99분위로 설정) SMAPE가 비율 오차라 스파이크를 캡핑하면 오히려 손해임을 확인하고 기각했습니다. 음수(환불, 전체의 0.014%)도 무시 가능한 수준으로 확인되어 그대로 둡니다.

### 2. 피처 엔지니어링 — `features.py` (49KB, 최대 모듈)

**핵심 규약: 테스트 시점에 실제로 쓸 수 있는 정보만 쓴다.** 창 통계는 주어진 28일 안에서만 계산하고, 작년 동기 비교(YoY)는 학습기간이 1.5년뿐이라 효과가 없어 제외했습니다.

v24 기준 활성 피처 54열은 6개 그룹으로 구성됩니다.

| 그룹 | 열 수 | 내용 | 대표 피처 |
|---|---|---|---|
| `win` (창 통계) | 14 | 28일 창 전체의 평균·표준편차·최댓값·중앙값·추세 등 | `w_mean`, `w_std`, `w_last7`, `w_trend` |
| `dow` (요일 통계) | 5 | 예측 대상일과 같은 요일의 창 내 통계 | `d_mean`, `d_last`, `d_nzratio` |
| `closed` (휴점 보정) | 6 | 업장 휴점일 비율·휴점 제외 평균 (업장별 13~46% 휴점 보정) | `st_closed_ratio`, `w_mean_open` |
| `cal` (달력·도메인) | 13 | 요일·월·공휴일·공휴일 전날 + 화담숲 개장/폐장·스키시즌 등 도메인 플래그 | `is_holiday`, `dow`, `month` |
| `ctx` (문맥) | 4 | 지난주 같은요일 값, 업장 집계, 예측 horizon(1~7) | `sd_lastweek`, `horizon` |
| `item` (품목 정적속성) | 7 | 업장·군집·카테고리·가격등급(5단계, 순서형 유지) 등 | `store`, `cluster`, `price_band` |

가격은 원본 숫자보다 **5단계 등급(순서형 숫자)**으로 두는 것이 더 낫다는 것을 실험으로 확인했습니다(범주형으로 바꾸면 순서 정보가 사라져 오히려 악화). `F.active_columns()` / `F.active_names()`를 통해서만 피처를 가져오도록 강제해, 기각된 그룹(`prof`: 요일 프로파일, `resort`: 리조트 전체 집계)이 조용히 다시 섞여 들어가는 사고를 방지합니다(실제 사고 2회 기록).

### 3. 모델 — `model_lgbm.py`

| 설계 | 값 | 근거 |
|---|---|---|
| 목적함수 | `regression_l1` (L1) + `log1p(y)` 타깃 | 수요 데이터가 우편향이고 L1이 SMAPE와 더 잘 정렬됨 |
| 학습 대상 | `y ≠ 0`인 행만 | 실측 0은 채점 제외 대상 → 0을 섞어 학습하면 예측이 전반적으로 내려앉음(내부 검증 0.895→0.543) |
| 예측 하한 | 1.0 | 채점 대상 행은 항상 `|A|≥1`이므로 1 미만 예측은 수학적으로 항상 손해(증명·검증 완료) |
| 시드 앙상블 | (42, 7, 2024, 913, 31) 5개 평균 | 시드 노이즈 완화 |
| v24 최종 하이퍼파라미터 | `num_leaves=127, feature_fraction=0.65, min_data_in_leaf=40, bagging_fraction=0.85, lambda_l2=1.0, lr=0.05, 1000 rounds` | 아래 "닫힌 축" 참조 — 이 조합이 나오기까지 79개 설정 탐색 |

> ⚠️ `model_lgbm.py`의 기본 `PARAMS`는 v1(기준선) 설정이고 v24가 아닙니다. v24 설정은 `run_phase18_prune_submit.py`가 자체 보유합니다. 한 번은 CV 최고점(leaves511·재튜닝) 설정을 채택했다가 실제 리더보드에서 꼴찌(0.487)를 찍고 되돌린 이력이 있습니다 — **모델 용량을 키우는 방향의 CV 개선은 신뢰하지 않는다**는 규칙이 여기서 나왔습니다(관측 4건에서 CV↔LB 격차가 용량에 비례해 +0.009→+0.023로 커짐).

### 4. 후처리 보정 — `make_submission.py` (개선의 77%를 만든 모듈)

원본 예측(.npy) 하나에 함수만 갈아 끼워 제출본을 만드는 커맨드라인 도구입니다. 재학습이 없어 시드 노이즈가 0이라 **문턱(threshold) 없이 바로 비교 판정**할 수 있습니다.

```bash
python src/make_submission.py final --raw experiments/phase18_prune3_raw.npy \
       --seg 0.55,0.90,1.02 --t 1.8,10 --snap geom
```

보정은 정해진 순서로 적용됩니다: **배율(3구간) → 하한(max) → 정수 스냅**. (하한을 배율 뒤에 한 번만 걸어야 함 — max는 비선형이라 순서가 결과를 바꿉니다.)

- **3구간 후보정** — 예측을 크기 구간별로 진단하니 작은 값은 과대예측, 큰 값은 과소예측되어 있었습니다(`p<1.8 → ×0.55 · 1.8~10 → ×0.90 · ≥10 → ×1.02`). 임계값 2.0은 이후 내부 고원 [1.70, 1.90]의 중앙인 1.8로 재조정했습니다.
- **정수 격자 스냅** — 위에서 설명한 로그비율 대칭성 기반. 자유 파라미터 0개.
- **중복 피처 제거** — 창 통계 11개가 상관 0.95~0.98로 뭉쳐 있었습니다. "그림자 대조(Boruta식 귀무 검정)"로는 잡음 피처가 0개였지만, 사다리형 단계적 제거 실험(사전등록)으로 3개(`w_posmedian`, `w_last14`, `w_std`)를 제거했을 때 +0.0015를 확인했습니다. 즉 가치는 "잡음 제거"가 아니라 **중복 비용 제거**(`feature_fraction=0.65`의 확률적 열 선택에서 중복 열이 선택 확률을 희석)에 있었습니다.

### 5. 검증 체계 — `validate.py` · `metrics.py`

`metrics.py`는 대회 공식 수식을 코드로 그대로 구현합니다.

```
Score = Σ_s  w_s · ( 1/|I_s| · Σ_{i∈I_s} ( 1/T_i · Σ_t 2|A-P| / (|A|+|P|) ) )
```

품목 안에서 유효 날짜끼리 평균(①) → 업장 안에서 품목끼리 단순 평균(②, 희귀 품목도 1표) → 업장끼리 가중합(③) 순으로 **세 번 평균**하는 구조입니다. 전체 행을 그냥 평평하게 평균하는 방식(`flat_smape`, 비교용으로 별도 구현)은 주력 품목에 쏠려 실제보다 후하게 나온다는 것을 확인했습니다.

`validate.py`는 대회 구조(28일 창 → +1~+7일)를 그대로 재현한 롤링-오리진 검증기입니다. **계절별 3~4개 폴드**(가을/겨울/봄, 이후 근거리·원거리로 세분화되어 4폴드)로 나눠 각각 채점 후 균등 평균합니다. 원거리 폴드가 필요했던 이유는 아래 "검증에서 발견한 것" 참조.

### 6. 앙상블·모델 이식 — `make_ensemble.py` · `model_ridge_tm.py`

`make_ensemble.py`는 제출 CSV 여러 개를 등가중 평균해 다시 원본 예측(.npy) 형태로 되돌리는 도구입니다. CSV가 이미 있으면 **재학습이 0**이라 시드 노이즈 없이 판정 가능하고, 부수적으로 "이 CSV가 정말 이 원본 예측에서 나온 게 맞는가"를 대조하는 매핑 검증도 겸합니다.

`model_ridge_tm.py`는 팀원 저장소([`JongeunSong/-konjiam-menu-demand-forecast`](https://github.com/JongeunSong/-konjiam-menu-demand-forecast), MIT License)의 Bayesian NB-GAM 계열 global positive Ridge 모델을 이 저장소의 폴드 루프에서 호출할 수 있도록 이식한 것입니다. 원본은 전체학습→예측 단방향이라 OOF(out-of-fold) 예측이 나오지 않아 우리 모델과의 잔차 상관을 잴 수 없었는데, 이식 후 로그공간 상관 0.999882로 이식 검증을 통과시켰습니다. 이식 중 원본의 pandas 3.0 호환성 버그(`float` 배열을 `int64` 열에 대입할 때 `TypeError`)도 발견해 문서화했습니다.

### 검증에서 발견한 함정: 내부 CV가 실제 순위를 거꾸로 예측한 사건

### 핵심 발견 (점수 밖의 성과)

1. **테스트 연도가 학습 연도보다 전반적으로 약했습니다.** 같은 달력 구간을 학습연도와 비교하면 YoY 0.75~0.92(스키 성수기 0.76, 유일하게 11월만 1.29).
2. **모델의 "창 탄력성"은 0.31~0.49입니다.** 창을 인위로 30% 약화시키는 반사실 실험에서 예측은 그 절반도 따라가지 않았습니다 — 나머지는 학습연도에서 외운 절대 수준입니다.
3. **그런데 그 암기는 결함이 아니라 트레이드오프입니다.** 창이 예고할 수 없는 전환기(스키 개막 램프 등)를 달력 기억이 메꿉니다. 암기를 강제로 제거한 실험(창 상대 타깃)은 겨울에서 −0.019~−0.047로 참패했습니다.
4. **이론적 하한선**: 같은 품목·요일·연속 5주의 실측 변동성(CV 중앙값 52%)만으로 계산한 이론 하한이 겨울 0.427~0.450 — 우리 겨울 성적(0.435)은 **이미 그 하한 안**입니다. 개선 여지는 봄에만 0.03~0.05 남아 있습니다.

## 🌦️ Tier B 확장 트랙 — 외부 데이터로 대회 규정 밖까지

Tier A(v24, 0.4376)까지는 외부 데이터를 전혀 쓰지 않았습니다. 이후 팀은 두 단계로 외부 데이터를 결합했습니다.

### x1 — 방문객수 결합 (수영)

광주시 방문자수 데이터(공공데이터포털) 3열을 v24 위에 추가해 Private **0.4360**을 달성했습니다.

### x3 — 품목별 날씨 민감도 "메뉴 반응" 피처 (차민, TB7)

x1은 "오늘 손님이 몇 명 오는지"는 알았지만 **온 손님이 무엇을 사 먹는지**는 몰랐습니다. 날씨는 방문객 수보다 메뉴 선택을 바꿉니다 — 같은 1,000명이 와도 30℃면 아이스 음료가, 영하권이면 국밥이 나갑니다. 이 "메뉴 반응"을 품목당 계수(베타) 2개로 압축한 피처를 추가해 Private **0.4327**(x1 대비 −0.0033, 분해능 0.003을 넘는 확실한 개선이자 **Tier B 신기록**)을 얻었습니다.

**피처 구성**은 열 딱 2개입니다.

```
wxb_ta   = 온도베타[품목] × 그날 기온이 평년 대비 얼마나 다른가 (기온 이상치)
wxb_rain = 강수베타[품목] × 그날 비가 오는가 (1mm 이상 여부)
```

베타는 원본 값이 아니라 **편차끼리** 비교해 계산합니다: 판매 편차는 `log(오늘 판매) − log(직전 28일 평균)`, 기온 이상치는 `오늘 평균기온 − 전후 15일 이동평균`(계절 성분 제거 — 원본 기온을 쓰면 "여름=아이스"라는, 달력 피처가 이미 아는 정보를 중복 학습하게 됨). 온도베타는 두 편차의 상관계수, 강수베타는 비 온 날과 맑은 날의 판매 편차 평균 차이입니다. 누출 방지를 위해 베타는 항상 학습 구간 데이터로만 계산합니다.

실제 추정값 예시(193품목 중 188개 추정): 카페테리아 카페라떼(HOT) 온도베타 −0.4(더우면 안 팔림), 담하 봉평메밀 물냉면 온도베타 +0.2(더우면 잘 팔림), 화담숲카페 아메리카노 ICE 강수베타 −1.0(비 오면 급감, 야외 매장).

**기존 날씨 실험(TB2 계열, 5회 시도)에서는 왜 안 됐는가**: 날씨 원값 3열만 주고 트리가 "음료 품목 AND 더운 날 → 증가" 같은 상호작용을 스스로 찾아내길 기대했지만, 품목마다 반응 방향이 반대라(아이스↑ 국밥↓) 얕은 분기에서 상쇄되어 보이지 않았습니다. x3는 이 상호작용을 베타로 미리 조립해(1차 피처화) 방문객수 위에 얹은 것이 핵심 차이입니다. 검증 과정에서 **플라시보 검정 3종**(무정보 난수, 날씨를 180일 굴려 정렬만 파괴한 시계열 등)으로 "겨울 구간 손실의 원인이 열 개수 때문이 아니라 계절 밖 외삽 실패 때문"임을 분리해 확인했고, 최종적으로 전면 적용(x3)이 봄 구간 한정 적용(x3s)보다 우수함을 확인해 제출했습니다.

### Tier B에서 시도했으나 검증 게이트를 통과하지 못한 것들

- TB1~TB6: 화담숲 실제 개장일 반영, 날씨 원값 직접 투입(게이팅 유무 포함), 네이버 검색어트렌드(당일/원인/래그 3버전), 메뉴명 임베딩 유사도, 스키장 실제 폐장일 — 전부 내부 게이트 미달로 기각. 상세 사유는 `experiments/log_tierb.md`.

## 🔭 인수인계 — 아직 열려 있는 것

### 아직 안 닫힌 합법(Tier A) 축

- **봄 전환기 타이밍을 창 안에서 읽어내는 피처.** `config.py`의 화담숲 개장일 상수는 3/20이지만 실측은 3/29~31입니다. 달력 상수 기반 피처는 이미 실패했으므로(트리가 `month`·`day`로 이미 만들 수 있는 정보라 희석 비용만 남음), 남은 여지는 **창 28일 안에서 개장 시점 자체를 감지**하는 설계입니다.
- **드리프트 강건화 변형.** 창 상대 타깃(절대 수준 암기 제거)은 기각됐지만, 앵커를 더 안정적으로 잡는 절대/상대 혼합 타깃은 아직 시도되지 않았습니다.

### 외부 데이터로 노려야 할 것 (Tier B, 측정 근거 있음)

1. **드리프트 보정(최우선)** — 예약률·투숙객수·객실 점유율처럼 "올해가 작년보다 얼마나 약한가"를 직접 알려주는 신호. 창 28일은 이를 늦게, 절반만 알려줍니다.
2. **봄** — 이론 하한과 유일하게 거리가 남은 계절(겨울은 이미 하한 안).
3. **야외 업장 날씨의 업장군별 분리 적용** — 화담숲·느티나무처럼 날씨 민감도가 구조적으로 다른 업장은 전 업장 공통 피처로 넣으면 방향이 반대라 상쇄되므로, 업장군을 나눠 시험해야 합니다(x3가 품목 단위로 이 문제를 해결한 선례).

### 이어받을 때 지키면 좋은 것

`experiments/log.md`를 먼저 읽고 같은 축을 다시 파지 않을 것, 짝시드 A/B로만 비교할 것, 사전등록 후 결과를 볼 것, 정수 스냅 이후가 아니라 `하한만(raw)` 상태에서도 반드시 재검증할 것, 후처리 체인은 그대로 유지한 채(개선의 77%가 여기서 나왔고 모델과 직교합니다) 모델만 바꿀 것.
