교차 조건 T→V 결과 — ColBERT 검색 + 페이지 이미지 입력
MMLongBench-Doc | 60문서 / 266문항 / 1,780페이지 / 144·72·36 DPI
====================================================================================

  설계
    검색  ColBERT v2 (MinerU OCR 텍스트 색인)  — T→T와 동일
    입력  해당 페이지의 PNG 이미지              — V→V와 동일
    생성  Qwen2.5-VL-7B, 프롬프트·top-5·greedy 동일

  왜 필요한가
    기존 두 조건은 검색 방식과 입력 형태가 함께 바뀌어 있어 원인 분리가
    불가능했다. T→V는 T→T와 '입력 형태'만, V→V와 '검색 방식'만 다르다.

      T→V vs T→T : 같은 페이지를 줬을 때 이미지가 나은가 OCR 텍스트가 나은가
      T→V vs V→V : 같은 이미지를 줬을 때 검색기 차이가 얼마인가

  정합성 검증
    Recall@5가 T→T와 세 DPI 모두 정확히 일치 (70.7 / 69.9 / 50.0%)
    입력 토큰이 V→V와 사실상 동일 (11,608 vs 11,616 / 2,966 vs 2,968 / 811 vs 811)
    → 의도한 대로 한 변수만 바뀌었음이 확인된다.

================================================================================
[7] 해석
================================================================================

1. 입력 형태를 바꾸는 것만으로 큰 폭이 회복된다
   검색을 ColBERT로 고정한 채 입력만 OCR 텍스트 → 페이지 이미지로 바꿨을 때
   답변 정확도가 37.6% → 51.1% (144 DPI), 12.0% → 21.1% (36 DPI)로 오른다.
   검색 성공 시 정확도는 47.3% → 65.4%로 18.1%p 상승한다.
   같은 페이지를 봤는데도 이만큼 차이가 난다는 것은, T→T의 손실 상당 부분이
   검색이 아니라 OCR 텍스트의 정보 손실에서 왔음을 뜻한다.

2. 검색 방식의 효과는 생각보다 작다
   144 DPI에서 V→V - T→V = 6.8%p에 불과하다. 전체 격차(V→V - T→T = 20.3%p)의
   3분의 1이다. 나머지 3분의 2(13.5%p)가 입력 형태에서 온다.
   36 DPI에서는 더 극단적이어서, 입력 형태 효과 9.0%p / 검색 방식 효과 2.3%p로
   전체 격차의 80%가 입력 형태 때문이다.
   → "비전 RAG가 우수하다"의 핵심은 ColPali의 검색력이 아니라
     페이지를 이미지 그대로 생성기에 넘긴다는 점에 있다.

3. 검색 성공 시 정확도에서는 T→V가 V→V를 앞선다
   144 DPI 65.4% vs 63.1%, 72 DPI 56.5% vs 56.7%(동률), 36 DPI 29.3% vs 25.8%.
   ColBERT가 찾아낸 페이지의 '질'이 ColPali보다 낮지 않다는 의미다.
   ColPali는 더 많이 찾아내지만(R@5 84.6% vs 70.7%), 찾아낸 것 중 답이 되는
   비율은 오히려 ColBERT 쪽이 약간 높다.

4. 36 DPI에서도 이미지가 낫다
   T→V 21.1% vs T→T 12.0%. 811토큰짜리 저해상도 이미지조차 662자로 쪼그라든
   OCR 텍스트보다 정보량이 많다.

5. 한계
   T→V는 실용적 파이프라인이 아니다. 검색을 위해 OCR을 돌려야 하므로
   OCR 비용을 그대로 지불하면서 생성에서는 그 결과를 버린다.
   이 조건의 가치는 성능이 아니라 원인 분해에 있다.
