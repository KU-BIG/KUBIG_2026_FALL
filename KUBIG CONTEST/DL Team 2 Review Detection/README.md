## 1. 문제 정의

### 왜 어려운 문제인가

| 제약 | 내용 | 이게 왜 문제인가 |
|---|---|---|
| 상품 단위 표본 부족 | 상품 하나당 리뷰 수십 건, 관측기간 짧으면 6개월대 | 시계열 모델이 "정상 vs 비정상"을 구분할 기준 자체를 학습할 데이터가 없음 |
| 도메인 집계는 결함을 희석시킴 | 리뷰 22만 건을 도메인 5개로만 집계 | 상품 하나의 결함은 그 도메인 수만 건 평균에 묻혀 안 보임 (반 전체 평균으로는 학생 한 명의 성적 급락을 못 알아채는 것과 같은 구조) |
| "그럴듯한 결과"와 "통계적으로 유의한 결과"는 다르다 | Prophet이 찾은 변곡점, 단일 hold-out 개선률 등은 점추정치일 뿐 | 재검증 없이 발표하면 우연을 결함으로 오인할 위험이 큼 |
| 도메인마다 데이터 성격이 다름 | 부정비율 평균이 IT기기 9.8%부터 화장품 23.7%까지 편차, RDate(날짜) 결측률도 도메인마다 다름 | 한 도메인에서 통한 설계가 다른 도메인에서 실패함 (아래 시행착오 로그 참고) |

### 이 프로젝트가 답하려 한 질문

> "제품 결함이 도메인 전체 통계에 드러날 때까지 기다리지 않고, 리뷰 텍스트만으로 더 일찍 알아챌 수 있는가?"

"예언"이 아니다. 미래에 없던 결함을 미리 맞히겠다는 게 아니라, **이미 리뷰에 남아 있지만 도메인 평균에는 묻혀 있는 신호를, 상품 단위로 내려가서 더 이른 시점에 잡아내겠다**는 뜻이다.

## 2. 파이프라인 (6단계)

```
원본 리뷰 텍스트 (225,285건, 5개 도메인)
        │
        ▼
┌─────────────────────────────────────────┐
│ 1. 전처리                                  │
│    정규식 정제 + Kiwi 형태소분석             │
│    (규칙기반·통계, 딥러닝 아님)              │
└──────────────────┬────────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│ 2. 임베딩                                  │
│    Sentence-BERT (jhgan/ko-sroberta-      │
│    multitask), 768차원 벡터로 변환          │
│    (DL, 사전학습 재사용. 추론만, 재학습 없음) │
└──────────────────┬────────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│ 3. 속성추출                                │
│    KLUE-BERT 파인튜닝, multi-label         │
│    BCEWithLogitsLoss + pos_weight         │
│    (DL, 역전파로 실제 학습)                 │
└──────────────────┬────────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│ 4. ABSA (속성 기반 감성분석)                │
│    KLUE-BERT 파인튜닝, 문장쌍 3-class       │
│    CrossEntropyLoss + class_weight        │
│    (DL, 역전파로 실제 학습)                 │
└──────────────────┬────────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│ 5. 토픽모델링                              │
│    SBERT 임베딩 + UMAP + HDBSCAN           │
│    + c-TF-IDF 키워드 추출                  │
│    + NPMI coherence 정량 검증(gensim)      │
│    (DL 임베딩 + 비DL 클러스터링 혼합)        │
└──────────────────┬────────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│ 6. 시계열분석                              │
│    Prophet(변곡점) + DLinear/NLinear       │
│    + NHiTS/N-BEATS(상품 단위 전역학습)      │
│    + QuantileRegression(확률적 예측)       │
│    (통계 + DL 혼합)                        │
└──────────────────┬────────────────────────┘
                   ▼
            월별 조기탐지 후보
```

각 단계에서 어떤 게 "진짜 딥러닝 학습"이고 어떤 게 "사전학습 모델 재사용"인지, 어떤 게 통계/규칙기반인지 구분해서 다뤘다:

- **규칙기반/통계**: 1단계 전처리 (Kiwi는 사전+통계 기반 형태소분석기, 신경망 아님)
- **DL · 추론만**: 2단계 임베딩 (Sentence-BERT 사전학습 가중치 그대로 사용, 파인튜닝 없음)
- **DL · 학습(역전파)**: 3·4단계 (KLUE-BERT를 우리 데이터로 직접 파인튜닝. `BCEWithLogitsLoss(pos_weight=...)`, `CrossEntropyLoss(class_weight=...)`로 손실함수를 클래스 불균형에 맞게 직접 설계하고, 역전파로 사전학습 가중치를 갱신)
- **혼합**: 5단계(비지도 클러스터링 + DL 임베딩), 6단계(통계적 분해 Prophet + DL 시계열 모델)

## 3. 핵심 방법론: 왜 "전역학습"이 필요했나

상품 하나만으로 시계열 모델을 학습시켜본 첫 시도는 실패했다. 패션 상품 1개(리뷰 22건, 관측기간 10개월)로 NHiTS를 학습시켰더니 과적합만 일어났다. **애초에 "정상과 비정상을 구분할 기준" 자체를 배울 데이터가 없었다.**

해결책은 상품 하나로 학습하는 대신, **같은 도메인(또는 여러 도메인)의 수백 개 상품을 하나의 모델에 묶어 함께 학습**시키고, 평가는 목표 도메인에만 한정하는 것이었다(다중 시계열 공유학습, darts 라이브러리). 패션의 경우 5개 도메인 전체 1,156개 상품을 학습에 쓰고, 평가는 패션 110개 상품에만 적용했다.

## 4. 검증: 시행착오를 그대로 남긴다

"처음부터 다 잘 됐다"고 쓰면 거짓말이다. 아래는 실제로 실패했다가 성공한 순서 그대로다.

### 4-1. 화장품 도메인 (조): NHiTS 상품단위 조기탐지 모델

| 차수 | 시도 | 결과 | MAE |
|---|---|---|---|
| 1차 | 스케일링 없이 학습 | **FAIL**. 모델이 naive와 소수점까지 완전히 동일. 아무 신호도 못 받으면 모델도 마지막 값을 베끼는 게 최선의 선택이 된다 | NHiTS = naive = 0.1937 |
| 2차 | 상품별 스케일링 추가 | **FAIL**. 가설(스케일 문제)이 틀렸음이 확인됨. 진짜 원인은 스케일이 아니라 다음 달을 가늠할 정보 자체가 없었기 때문이다 | 0.1932 |
| 3차 | 그 달 실제 리뷰수를 past covariate로 추가, epoch 50→75 | **PASS**. "이번 달 리뷰가 몰렸다"를 모델에 직접 알려주니 베끼기를 벗어나 진짜 패턴을 학습했다 | 0.1937 → 0.1801 (7.0%↓) |
| 4차 | 롤링 백테스트(212개 상품·1,271윈도우, walk-forward) | **PASS**. 단일 hold-out이 우연이 아님을 재확인 | naive 0.1674 → NHiTS 0.1541 (7.9%↓) |
| 5차 | 통계적 유의성 검정(부트스트랩·Wilcoxon) | **PASS(부분)**. 평균(부트스트랩)은 유의, 순위(Wilcoxon)는 비유의. 소수 상품의 큰 개선이 평균만 끌어올린 구조다 | bootstrap 95% CI [0.0041, 0.0224] · Wilcoxon p=0.9028 |

### 4-2. 패션 도메인 (손): NHiTS 5도메인 통합 전역학습

| 차수 | 시도 | 결과 |
|---|---|---|
| 1차 | 패션 리뷰 전체를 "월별 부정비율" 하나의 시계열로 집계(82개월), Prophet으로 분석 | **FAIL**. MCMC 검증 결과 비유의, naive가 더 우월. 도메인 전체로는 시계열 신호를 잡을 수 없다 |
| 2차 | 패션 단독 85개 상품 각각 계절성 feature 추가, 도메인 상품 기준 완화(110개 상품) | **FAIL**. 성능이 더 나빠지거나 naive와 비슷. 원인은 데이터 부족(관측기간 중앙값 6.1개월)이었다 |
| 3차 | 5개 도메인 통합 학습(총 1,156개 상품 학습, 패션 상품 110개만 평가) + feature 추가 | **PASS**. 최종 성능 MAE 0.1253, 롤링백테스트 10.9% 개선. 통계검정 완료: **부트스트랩 유의 · Wilcoxon p=0.0077 유의(팀 내 유일하게 둘 다 통과)** |

## 5. 통계적 검증 방법론

이 프로젝트가 가장 공들인 부분이다. "그럴듯해 보이는 결과"를 그대로 내세우지 않고, 아래 4가지로 재검증했다.

**① Baseline 비교**: naive(마지막 관측값 그대로 예측), 도메인평균과 MAE로 비교. 처음부터 "복잡한 모델이니까 당연히 낫다"고 가정하지 않았다 (실제로 화장품 1차 시도, IT기기 단위1 등에서 naive에게 진 경우가 여러 번 나왔다).

**② 롤링 백테스트**: 단일 hold-out(마지막 2개월)만으로는 우연인지 알 수 없다. `darts.historical_forecasts(retrain=False)`로 재학습 없이 시점만 2개월씩 밀어가며(walk-forward) 여러 시점에서 반복 예측·검증했다.

**③ MCMC(NUTS 샘플러, 300 샘플)**: Prophet이 찾은 변곡점은 delta 점추정치(MAP)일 뿐이다. 각 변곡점 delta의 사후분포를 MCMC로 추정해서 95% 신뢰구간이 0을 포함하는지로 "그럴듯함"을 통계적으로 검정했다. **결과: 생활·화장품·패션 3개 도메인 전부, 그럴듯해 보이던 변곡점이 통계적으로는 비유의했다.** 패션에서는 델타 점추정치만 봤을 때 유력해 보였던 변곡점 4개를 포함해 상위 10개 후보 전부 95% 신뢰구간이 0을 통과했다.

**④ 부트스트랩(10,000회 재표본) + Wilcoxon 부호순위검정**: 상품 단위 개선이 우연이 아닌지 이중으로 검증했다. 부트스트랩은 naive오차−NHiTS오차의 평균 차이에 대한 신뢰구간을 구하고, Wilcoxon은 분포 가정 없이 순위 기준으로 재검증한다. **이 둘이 항상 같은 결론을 내지는 않았다.** 화장품·생활은 평균(부트스트랩)으로는 유의했지만 순위(Wilcoxon)로는 비유의했다. 이는 naive가 이기는 "조용한" 구간이 다수 존재하고, NHiTS는 소수의 변동성 큰 구간에서 크게 이기는 구조이기 때문이다. 이 차이를 숨기지 않고 그대로 보고했다.

## 6. 도메인별 결과

| 도메인 | 담당 | naive 대비 개선 | 검증 단계 | 통계적 유의성 |
|---|---|---|---|---|
| **IT기기** | 채 | **25.3%↓** | 롤링백테스트(156개 상품·807윈도우) | 검정 미실시 |
| **패션** | 손 | **10.9%↓** | 롤링백테스트+GPU재현, 5도메인 통합학습 | ★ 부트스트랩+Wilcoxon 둘 다 통과(팀 내 유일) |
| **생활** | 조 | **14.3%↓** | 롤링백테스트(245개 상품·1,487윈도우) | 부트스트랩 유의 · Wilcoxon 비유의 |
| **화장품** | 조 | **7.9%↓** | 롤링백테스트(212개 상품·1,271윈도우) | 부트스트랩 유의 · Wilcoxon 비유의 |
| **가전** | 김 | **6.2%↓** | 단일 hold-out만(N-BEATS) | 검정 미실시 |

개선률이 가장 큰 게 가장 신뢰도 높은 결과는 아니다. 패션(손)이 팀 내 유일하게 통계검정 2종을 모두 통과했고, 가전은 아직 단일 hold-out 단계에 머물러 있다.

### 도메인별 구체적 발견

- **IT기기: 갤럭시Z 폴드3, 폴딩 힌지·화면 내구성 결함.** 예측구간 이탈 후보 77건 → 리뷰 4건 이상 신뢰가능 31건 → 그 상품 자체 역대 최고치 초과 7건. 그중 갤럭시Z 폴드3는 2개월 연속 후보로 잡혔고(실제 부정비율 40.0%→50.0%, 과거 평균 5.8%, 과거 역대 최고 22.2%), 그 시기 원문 리뷰 5건 전부 "필름내부 이격→오작동", "화면 주름", "스크래치", "떨어뜨린 적 없는데 꺼짐" 등 같은 결함(폴딩 힌지/화면)을 가리켰다. 팀 내 가장 설득력 있는 단일 사례.
- **화장품: "콘실러 파우더" 등 10개 상품이 역대 최고치 초과 급증.** 신뢰가능 후보 35건 중, 그 상품 역사상 처음 보는 수준까지 튄 "진짜 신규 급증"만 걸러낸 최종 리스트.
- **생활: "청소용 변기세정제" 등 4개 상품에서 이례적 급증.** 화장품과 동일한 2단계 필터(예측구간 이탈 → 자체 역대 최고치 대조)로 확인.
- **패션: "옷 냄새·세탁" 불만 토픽 급증 + 방법론적 자기검증.** 그럴듯해 보이던 변곡점을 MCMC로 팀 스스로 반박했고, 통계검정 2종 모두 통과(팀 내 유일)한 방법론적 기여가 가장 큰 성과다.
- **가전: 후보 67건 확보, 검증은 다음 단계로 남겼다.** 시간 안에 원문 대조까지는 못 갔지만, 다른 도메인에서 신뢰가능 후보의 71~92%가 실제로는 새 급증이 아니었던 걸 고려해 신중하게 미검증으로만 제시한다. 단위1(도메인집계)에서는 DLinear가, 단위2(상품단위)에서는 N-BEATS가 naive를 이겼다.

## 7. 정직한 한계

과장하지 않는 것 자체가 이 프로젝트의 신뢰도라고 생각한다.

- 도메인 전체 집계 수준의 Prophet 변곡점은 MCMC 검증 결과 **통계적으로 유의하지 않다** (생활·화장품·패션 3개 도메인 모두 동일)
- 상품 단위 개선은 "평균으로는" 유의하지만 "매번 이긴다"는 아니다(Wilcoxon 비유의). naive가 이기는 조용한 구간이 더 많다
- 경량 선형모델(DLinear/NLinear)은 상품 단위 검증에서 생활·화장품·IT기기 3개 도메인 모두 naive에게 졌다. "단순한 모델이 항상 낫다"는 통념이 이 데이터엔 안 맞았다
- 5단계 catch-all 토픽(전체의 20~30%)은 outlier 강제배정(`reduce_outliers`)의 부작용이다. "0%"라는 숫자는 클러스터링이 완벽하다는 뜻이 아니라, 애매한 리뷰를 기계적으로 가장 가까운 토픽에 배정한 결과다. 원문 샘플 대조로 실제 정확도(~75%)를 별도 검증했다
- **가전은 조기탐지 후보(67/238개)를 원문·자체기준선으로 검증하지 못했다.** 롤링백테스트/통계검정까지 도달한 4/5 도메인(생활·화장품·패션·IT기기)과 달리 baseline 비교 단계에 머물러 있다. 시간 제약상 의도적으로 여기서 마무리했다

## 8. 배운 점

1. **도메인 평균은 신호를 숨긴다.** IT기기 전체 그래프에선 변곡점이 0개였지만, 상품 단위로 보니 갤럭시Z 폴드3의 급증이 뚜렷했다.
2. **전역학습이 데이터 부족을 해결한다.** 상품 하나는 리뷰가 짧아도, 같은 도메인 수백 개를 묶어 학습하면 5개 도메인 전부 naive baseline을 유의하게 이겼다.
3. **정직한 검증이 결과보다 중요하다.** 변곡점(3개 도메인)은 MCMC로, 상품 단위 개선은 Wilcoxon으로 재검증하니 둘 다 일부는 비유의했다. 그 결과를 그대로 보고했다.
4. **단순한 모델이 늘 낫다는 통념은 틀렸다.** 경량 선형모델은 3개 도메인 모두 패배했고, 계층적 구조를 가진 NHiTS·N-BEATS는 5개 도메인 전부에서 승리했다.

그래서 이 접근은 새 결함이 도메인 평균에 드러날 때까지 기다리지 않고, 더 적은 리뷰로 더 일찍 알아챌 수 있게 한다.
